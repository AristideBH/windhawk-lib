# Explorer Extras Sidebar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Explorer's navigation pane with the mod's own sidebar (Favorites, Locations, Tags) that has collapsible sections, pinning by drop, hideable locations and a macOS-style tag list backed by a background index.

**Architecture:** A `DesktopWindowXamlSource` island covers the native pane (Details-pane technique); new parts under `explorer-extras/dev/src/` hold the tag list, the tag index, the sidebar panel, its three sections and the tag results view. Navigation goes through the existing `BrowseObject` path; labels keep the existing NTFS stream.

**Tech Stack:** C++/WinRT, WinUI 3 in an island, Win32 shell (IShellItem, IShellFolder, pin verbs), NTFS named streams, PowerShell UIA smoke tests, Windhawk build via `python explorer-extras/dev/build.py`.

**Spec:** `docs/superpowers/specs/2026-11-23-sidebar-design.md`

## Global Constraints

- Bump `@version` in `explorer-extras/dev/src/00-header.cpp` on every commit that changes the mod (this plan moves 1.0.20 to 1.1.0 at the end; bump the patch in between).
- Commit, merge and push only when Ari says so. Push only to his own repos.
- Source lives in parts `explorer-extras/dev/src/*.cpp`, joined by `python explorer-extras/dev/build.py` into `explorer-extras/explorer-extras.wh.cpp`. Never edit the generated file.
- Unload safety: every object on a window thread is released through `ReleaseClosedWindow`, `RevokeKeptThreads` or `CloseEverything`; new worker threads are joined through `WaitForThreadWork`; no `no_destroy` on plain containers.
- Windows tags are data: set text in code, never in XAML markup. Names in the stream are tab-separated lines; reject or escape tab and newline in tag names.
- Files written for rename and delete keep their last-write time (`SetFileTime(handle, nullptr, nullptr, &{0xFFFFFFFF, 0xFFFFFFFF})` before the write), as `03a-labels-store.cpp` does.
- XAML island: only opacity and translation transitions animate. Hover fills `SubtleFillColorSecondaryBrush`, pressed `SubtleFillColorTertiaryBrush`, selected 6% plus a 3 px `#60CDFF`-style accent pill (use the theme accent brush), selected and hovered 9%.
- Rows are 32 px, subheaders 32 px with 12 px text at 16 px left, body 14 px, section gap 6 px, panel padding 2 px by 8 px; no card background.
- Index scope: fixed local drives only; skip removable, network, OneDrive online-only files (`FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS`) and `Windows`, `Program Files`, `Program Files (x86)`, `ProgramData`.
- Sidebar tag count setting: default 4. Drives group from 3 entries up. One tag per results list.

## Review Focus

- Explorer unloading or a window closing while the index scans, or while rename and delete rewrite thousands of files (no crash, no half-written stream, work stops).
- Tag names with unusual content: tabs, newlines, `{`, very long names, a name that differs only in case, empty names (colour-only labels).
- A drive removed during a scan, reparse-point loops, paths over `MAX_PATH`, files locked by another process or without write access during a rewrite.
- No pinned folders, Quick access disabled by policy, or a pinned folder that no longer exists.
- A window that was open before the mod loaded (no `WindowState`), new tabs, a second window, light theme, 150% DPI.

## Ledger

- Task 1: complete. Pins and scan are PowerShell scripts, not Windhawk mods (Ruling: they need only shell and file calls, which a mod makes identically; no cost). The island probe needed the visible-pane rule (see PLAN.md).
- Task 2: complete (1.0.21; smoke test 0 failures, `TAGS SELFTEST pass`).
  - Ruling: a tag name is at most 40 characters (`kLabelsMaxName`), not 64 as the plan said, because the stream cuts names at 40. Cost if wrong: none; a longer limit would be cut on write.
  - Ruling: a tag is told apart by its name in any case; an unnamed label (empty name) is shown under its colour's setting name elsewhere in the mod, but the list holds only named tags. Cost: a colour-only label gets no sidebar entry until it is named.
  - Ruling: the list operations come in a pure form on a list (`TagListAddTo`, `TagListRenameIn`, `TagListRecolorIn`, `TagListSetHiddenIn`, `TagListRemoveFrom`, `TagListTouchIn`, `TagListEnsureIn`, `TagListRecentOf`, `TagListSerialize`, `TagListParse`) plus the saved-list wrappers of the plan's Interfaces block, so the self-test runs without touching the user's saved list.
