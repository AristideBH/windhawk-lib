# Labels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add macOS-style labels (coloured dots, optional names) to Explorer Extras: drawn on Explorer's own list in every view and in Columns, edited from the details pane and the right-click menu, filterable per folder.

**Architecture:** Tags live in one NTFS named stream per item. A worker thread fills a per-folder cache (displayed name to tags); a hook on `dui70.dll`'s exported `Element::PaintContent` draws dots and dims rows from that cache without touching the disk. Everything is new parts in `explorer-extras/src/`, joined by `build.py` like the rest of the mod.

**Tech Stack:** C++ (Windhawk mod, WinUI 3 via C++/WinRT, GDI for painting), Python (`build.py`, probes), PowerShell (deploy and smoke scripts).

**Spec:** `docs/superpowers/specs/2026-11-17-labels-design.md`. Probe code to reuse: `probes/probe-label-paint.wh.cpp` (paint, dim, tree walk), `probes/probe-ctx-hook.wh.cpp` (menu hooks). Confirmed layouts: `.claude/skills/windhawk-explorer-surfaces/SKILL.md`, section "Drawing on file list rows".

## Global Constraints

- Bump `@version` (minor) on every build; commit only when Ari asks, locally first, never touch the windhawk-mods registry or push the PR branch.
- No macro named `Wh_...` (use `LogVerbose`); no setting text with a colon followed by a space (`build.py` refuses it); no `__try`; no GDI+; no modal dialogs for notices.
- Every new global holding WinRT, a thread or a handle is `[[clang::no_destroy]]` and released explicitly in `Wh_ModBeforeUninit`/`Wh_ModUninit`; threads start with `StartModThread` and end in `JoinModThreads`; every XAML handler goes through `Keep`/`AddRouted` (revokers).
- Stream writes set the write handle's last-write time to `0xFFFFFFFF/0xFFFFFFFF` before writing (times must not change).
- At most 16 tags per item, tag names at most 40 characters. Palette: 7 colours plus neutral gray (index 0), light and dark variants. Dot: 8 px at 100 percent DPI, anti-aliased, no hard outline.
- Painting never touches the disk, never blocks, and switches labels off (with one log line) when a `dui70.dll` export or vtable slot is missing.
- Settings only on Windhawk's page, in a `labels` group of `settings.schema.json`.
- Debug build: `pwsh -NoProfile -File tools/deploy-explorer-extras.ps1 -Log <log>`; smoke: `tools/smoke-test-explorer-extras.ps1 -Log <log>`. Ari tests the visuals; ask before the first deploy of each task.

## Review Focus

- A folder with thousands of items or a slow disk: navigating away cancels the read; the window never stalls (Task 3).
- Two items with the same displayed name (hidden extensions): no dot on either, one notice in the pane (Tasks 3, 6).
- A tag name with `:`, tab, newline, `|` or emoji, 40 characters, or a stream that is corrupt or from a newer version: round-trips or is ignored without crashing (Task 1).
- A locked, read-only, cloud-only or non-NTFS target: greyed in advance, one inline notice on failure, nothing written (Tasks 1, 6).
- Theme or DPI change while a window is open, two windows on different monitors, unload while the flyout is open (Tasks 2, 4, 6).

### Task 1: Settings and the tag stream

**Interfaces:**
- Produces:
  - `struct LabelTag { uint8_t colour; std::wstring name; };` (colour 0 = neutral gray, 1 to 7 palette order red, orange, yellow, green, blue, purple, gray-blue chosen by the builder and recorded in the spec)
  - `std::wstring LabelsSerialize(std::vector<LabelTag> const&)`; `bool LabelsParse(std::wstring_view text, std::vector<LabelTag>* out)` (false on a corrupt or newer-version text)
