- What is tested by Ari, in short: everything through 0.32.1 (touch, settings window, columns,
  keys, menus, archives, columns per tab, per-folder memory, drag between
  columns, drag out to the navigation pane, other windows, the desktop and
  other apps, drops coming in, the drag label and drop frame, harmonized
  widths, the border handle, the Columns icon on the View button, connected
  selection). `ROADMAP.md` has the plan from here.
- Architecture in one paragraph. One WinUI panel per Explorer window, hosted
  as a `DesktopWindowXamlSource` over the file list, with a per-window
  `WindowState` used only on that window's UI thread. Folders and icons are
  read by one worker thread per window, results come back through the
  window's dispatcher queue and are dropped by generation or by a cancel flag.
  Each entry has a row shell at once and its content is built as the row comes
  near the screen. Explorer's own view stays under the panel and follows the
  active column, so the toolbar, panes and status bar act on the selection.
  Columns are per tab: the panel is hidden, not torn down, while a tab that is
  not in Columns shows, and each tab keeps a snapshot of its columns
  (`TabSnapshot`).
- Source layout: the mod is kept in parts under `explorer-extras/src/`
  (00-header, 01-includes, 02-core, 03-shell, 04-notify, 04a-memory, 05-state,
  06-worker-icons, 07-columns, 08-menu-edit, 09-input, 09a-drag, 10-viewmenu,
  11-window, 12-entry, joined in name order) and
  `explorer-extras/explorer-extras.wh.cpp` is generated by
  `python explorer-extras/build.py` (`--check` exits 1 when it is out of date).
  Never edit the generated file. A new area goes in a new numbered part. What
  each part holds:
  - 02-core: logging, settings values (the `g_` atomics), small helpers.
  - 03-shell: shell helpers, folder loading, sort and group reading.
  - 04a-memory: per-folder memory (sort and group, width, Columns per folder),
    kept in one Wh value, 150 folders.
  - 05-state: `Column`, `WindowState`, `DragState`, `TabSnapshot`.
  - 07-columns: columns, rows, selection, navigation of Explorer's view.
  - 08-menu-edit: the item and folder (background) flyouts, rename, clipboard, undo.
  - 09-input: keys, the tick, tab switching, the panel's show and hide.
  - 09a-drag: dragging rows between columns and out of the panel.
- Hooks: `FileExplorerExtensions.dll` command bar handlers (pointer press,
  `OnDpiChanged` for window creation, `InvokeMenuItem` for toolbar commands),
  `CreateWindowExW` for new tabs, `TranslateAcceleratorW` while the rename box
  has the keyboard, and `IShellBrowser::BrowseObject` (vtable slot 11) for the
  navigation trace and the sidebar click. See `PLAN.md` and the skills.
- Settings (under `columns:`): enabled, minWidth, maxWidth, followActiveColumn,
  restoreOnOpen, maxItems (5000), sidebarRoot, focusRect, compactScrollbars,
  doubleClickUp (off), headerKeyboard (off), archives (off), desktopRealOnly
  (off), remoteMarks (on), rememberSort, rememberWidth, rememberLayout (all on),
  harmonizeWidths (on), keepStale (on), dragOut (on), background (a test
  setting), debugLog.
  Since 0.24 every setting is declared once in `explorer-extras/settings.schema.json`
  (id, group, type, default, limits, name, description, page and card for the
  settings window). `build.py` writes the Windhawk settings block (marker
  `@@SETTINGS_BLOCK@@` in `00-header.cpp`) and the C++ table (`@@SETTINGS_TABLE@@`
  in `02a-settings.cpp`) from it: never edit the block in the header by hand, and
  read a setting with `SettingBool`, `SettingInt` or `SettingText` by its id.
  The schema also holds `features` (planned features shown as placeholder pages when
  the hidden `showUpcoming` setting is on), `whatsNew` (the Home card) and `strings`
  (every text of the window and the menus by id; use `Str(L"id")`, never a literal,
  so translations can come in).
  The build refuses a `$name` or `$description` with a colon followed by a space,
  which breaks the whole block (happened twice).

- Things that cost time and are worth knowing:
  - Compile check: `C:/Program Files/Windhawk/Compiler/bin/clang++.exe`, flags
    at the end of this file. `clang++` is not on PATH in the Bash tool, and a
    pipe into `grep error` then looks clean when nothing ran. Count matches.
  - Patching: write patch scripts with the Write tool, not a Bash heredoc
    (backslashes and private-use glyphs get mangled). The parts are CRLF or
    LF, so read with `newline=''` and normalise before matching.
  - Every handover bumps `@version` in `00-header.cpp` and the start log line
    in `12-entry.cpp`, builds, syntax-checks, copies to
    `C:/ProgramData/Windhawk/EditorWorkspace/mod.wh.cpp` (compare with `cmp`),
    and commits. Ari compiles and sends the log (`probes/logs/explorer-extras.log`).
  - Replacing the mod while a window is in Columns can hang or crash that
    window (a callback of the old DLL), seen once as `local@..._unloaded` in the
    Event Viewer. The first start after a reload is also slow (Windhawk).
  - Pidls made from a path are rooted under This PC, the columns' pidls under
    the Desktop. They never compare equal, so compare paths.
  - The shell gives a folder inside an archive a normal-looking path, so
    "inside an archive" means a part of the path is a file. Properties and
    Paste on items inside an archive crashed Explorer, only Copy is offered.
  - Rows mark their own press as handled: anything that starts from a row
    press (drag, stop-scroll) must hang on the handler registered with
    handledEventsToo (`stopScrollHandler`).
  - A tab made after the panel is a window above it and covers it; the tick
    raises the panel when `GetWindow(panel, GW_HWNDPREV)` is not null.
  - A move done by a shell drop target returns effect 0 ("none") on purpose.
  - For a real drag, a modifier key let go just before the button must still
    count (`OutDropSource`, 400 ms), and the drag loop does report Ctrl in the
    key state, but not before it is pressed.

## How the work loop runs

- The mod's debug log is `probes/logs/explorer-extras.log`. It is kept
  across restarts and each line has a thread id. Read it before guessing.
  That folder is in `.gitignore`: it holds the user's file names.
- Windhawk's window runs elevated. A session driving the screen can't
  click in it. Ari clicks Edit and Compile.
- With the computer linked and `C:\ProgramData\Windhawk\EditorWorkspace`
  writable for Ari's account, the source can be written straight into
  `EditorWorkspace\mod.wh.cpp` while the mod is open in the editor. Check
  the file's `@id` first, so another mod isn't overwritten.
- Compile errors land in `EditorWorkspace\compiler_errors.log`.
- Compiled mods are in `C:\ProgramData\Windhawk\Engine\Mods\arm64`. The
  file name carries the version, which shows what Ari actually ran.
- Copying a changed file from a cloud session to the PC has sent a stale
  copy several times. Use a new staged file name for each version and
  compare checksums on the PC before writing to the editor.
- The whole file, WinUI part included, can be syntax-checked with Windhawk's
  own clang, see the last section. Linking is still Windhawk's job.
- Test in a new Explorer tab opened with "+", and close it afterwards.
  Never navigate Ari's own tabs.
- The PowerToys command palette can count as the front window and block
  clicks. Ask for click access to it, don't work around it.

## Lessons from 0.3

- Never treat `this` of a command bar method as a XAML object.
- A coroutine moves its by-value arguments out of the caller's slot, so read
  them before the original runs.
- Look for a hook with a probe that hooks little and logs the full symbols,
  and raise the risk one step per run.

## Lessons from 0.2

- Never close or release XAML objects after their window is destroyed.
- A mod that logs into a folder it watches reloads forever. Own files are
  ignored and content changes don't trigger reloads.
- `MapColumnToSCID` has gaps. Don't stop at the first failure.
- When grouping is on, the group's property is also the first sort column.
- Two interfaces of one XAML object don't compare equal. Convert to the
  same type before comparing.

## Compile check without the Windhawk editor

Windhawk's own clang is at `C:\Program Files\Windhawk\Compiler\bin\clang++.exe`.
A syntax-only pass over the whole mod finds the compile errors in seconds:

```
clang++ -x c++ -std=c++23 -target x86_64-w64-mingw32 -DUNICODE -D_UNICODE \
  -DWINVER=0x0A00 -D_WIN32_WINNT=0x0A00 -D_WIN32_IE=0x0A00 -DNTDDI_VERSION=0x0A000008 \
  -D__USE_MINGW_ANSI_STDIO=0 -DWH_MOD '-DWH_MOD_ID=L"explorer-extras"' \
  '-DWH_MOD_VERSION=L"X.Y.Z"' -include windhawk_api.h -Wno-unused-parameter \
  -Wno-missing-field-initializers -Wno-cast-function-type-mismatch -fsyntax-only \
  -I"C:/Program Files/Windhawk/Compiler/include" explorer-extras/explorer-extras.wh.cpp
```
Run it before every handover. It does not link, so missing `-l` flags still
show up only in Windhawk.
